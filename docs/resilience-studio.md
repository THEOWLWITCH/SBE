# סטודיו חוסן — חיבור ובדיקות

סטודיו חוסן נמצא ב־`app/resilience-studio.html`. הוא מוסיף ל־Be Good מסלול מהשראה או נקודת מוצא חופשית לתקציר הניתן לעריכה, בחירת מוקד וערכת פעולה. תפקיד המוביל וגילו נשמרים בנפרד מאוכלוסיית המשתתפים. כל רכיב ומיומנות מוצגים על פי שלב שמתרגל אותם בפועל.

## החלטות חיבור

- המסכים סטטיים ב־Netlify; הנתיב החדש `/api/studio` נמצא בשרת Render הקיים. אין שינוי בספק או במודל של כלי המערכת האחרים.
- הרשאת `studio` מאפשרת לפתוח את הכלי בנפרד לקבוצות, נוער, משפחות, צוותים וקהילות. גם הרשאות `activity`, `resilience`, `practi` ו־`leadership` מאפשרות גישה. השרת בודק קוד, תוקף, מנוי ותקרת מוסד מחדש בכל פעולה מוגנת.
- המיפוי מועבר בבחירה מפורשת ממסך המיפוי. השרת מאמת הרשאת חוסן, מוסד ומפתח ניהול, ואז מחשב רק סיכום קבוצתי בעזרת מנוע הניקוד הקיים. אין ממוצע בין סבבים: נבחר סבב מסוים או המילוי האחרון של כל נשאל. שמות כיתה, מוסד, מזהי נשאלים, תשובות אישיות ומפתח הניהול אינם נשלחים למודל.
- בנק המקורות המקצועי הקיים נשאר מקור האמת. כתבי יד המסומנים `hidden` אינם נשלחים למודל ואינם מופיעים בערכה. גרסת המקורות היא חותמת SHA256 של הבנק. חומר משתמש נשאר מידע הקשר או השראה שטרם נבדקו; כתובת ללא תוכן מסומנת כבלתי נגישה.
- התוכן נשמר במכשיר לפי `sbeUserKey`, וניתן להעברה כקובץ עבודה אישי. אין שמירה אוטומטית של חומרי משתמש בשרת ואין קישור ציבורי לפעילות. קובץ העבודה כולל מידע אישי מהתקציר; הדפסת חומרי המשתתפים נבנית מהחלקים המשותפים בלבד.
- התאמה וגרסה מקושרת מוצגות כמועמדות. המשתמש בוחר אם לקבל; הפעילות הקודמת נשמרת בגרסאות. הסרת שלב מסירה גם את טענות המיומנות שנשענו עליו.

## מודל והפעלה

הסטודיו משתמש ב־GPT‑6.1 Sol דרך Responses API, עם reasoning ברמת `medium`, פלט JSON לפי סכימה קשיחה ו־`store:false`. הבקשה אינה כוללת `temperature` או `top_p`. [תיעוד המודל](https://developers.openai.com/api/docs/models/gpt-6.1-sol), [פלט מובנה](https://developers.openai.com/api/docs/guides/structured-outputs).

בשרת Render נדרשים:

| משתנה | שימוש |
|---|---|
| `OPENAI_API_KEY` | מפתח שרת; אין להכניס אותו לדפדפן או למאגר |
| `SUPABASE_URL`, `SUPABASE_SERVICE_KEY` | תשתית הרשאות קיימת |
| `STUDIO_MODEL` | אופציונלי; ברירת מחדל `gpt-6.1-sol` |
| `STUDIO_REASONING_EFFORT` | אופציונלי; `low`, `medium`, `high`, `xhigh` או `max` |

לאחר פריסת הקוד יש לפתוח את הרשאת הסטודיו למוסדות ולמשתמשים הרצויים. יש לבדוק כניסה עם קוד אמיתי ומיפוי מורשה, הפקה אמיתית, שגיאת מודל, פתיחה מחדש והדפסת עברית. הבדיקות המקומיות אינן מספקות ראיה לביצועי מודל חי או ליעילות מקצועית.

## מעמד התוכן

25 הרכיבים הם סינתזת התכנון בגרסה 1.0, מסומנים `draft`. הדוגמאות הן `example-draft`; הפקת המודל היא `new-ai` ויעילותה לא נבדקה. מעמד `existing-bank` מציין מקור בבנק הקיים ואינו אישור מקצועי לפעילות. לפני שימוש מקצועי בפועל נדרש אישור של הרכיבים, המנגנונים וכללי גיל, הובלה עצמאית וחירום. אין מדד חוסן אישי חדש ואין ניתוח טיפולי.

## בדיקות

השיחה החדשה מפעילה `action:consult` באותו נתיב מורשה. היא מקבלת תקציר חלקי, שאלה, שלב, חששות והיסטוריה מסוננת; ההצעה חוזרת תחת `consultation` ואינה מחליפה פעילות. `suggestedInstructions` חל רק על שלב שנבחר, ומחייב קבלה מפורשת ובדיקת תיוג בממשק. השיחה נשמרת בקובץ העבודה הפרטי; חומרי משתתפים וגרסאות לשיתוף אינם מכילים אותה.

הפעילות כוללת כעת `facilitationPlan` ותכנית `socialMechanism`. החוזה נשאר בגרסה 1.0: קבצים קודמים ללא החלקים האלה מקבלים שדות ריקים בעריכה, כדי לאפשר המשך עבודה. הפקות חדשות מחייבות תכנית הנחיה ומקור הנחיה מוכר. ראו `resilience-studio-claude.md` להמשך פיתוח עם Claude.

`cd harness && npm test` מריץ בדיקות Node ללא התקנת חבילות. תהליך GitHub Actions מריץ אותן על PR וב־main. הבדיקות מכסות חוזי פעילות, הרשאות בזמן אמת, בידוד המיפוי, סבבים, בקשת Responses, מקורות וניווט. במחשב Windows עם הגבלת גישה לספריות האב אפשר להריץ `node --preserve-symlinks --preserve-symlinks-main --test tests`.

בדיקות הדפדפן המקומיות משתמשות בנתוני בדיקה ובתשובות מודל סינתטיות בלבד. אין להשתמש בשמות כיתות או בנתוני נשאלים אמיתיים בנתוני בדיקה.

מיפוי הדרישות ותוצאות האימות מפורטים ב־[תרחישי הקבלה](resilience-studio-acceptance.md).
