## מה לקרוא ומה לערוך

קוראים תחילה את [`CLAUDE.md`](../CLAUDE.md), שבו כללי התוכן, העיצוב וההרשאות של Begood, ואז את [`resilience-studio.md`](resilience-studio.md), שבו החלטות החיבור, ההפעלה ומעמד התוכן. [`resilience-studio-acceptance.md`](resilience-studio-acceptance.md) ממפה דרישות לבדיקות ולפערים שנותרו.

| קובץ | תפקיד בפיתוח |
|---|---|
| `app/resilience-studio.html` | מסך הסטודיו והטפסים בעברית וב־RTL |
| `app/lib/resilience-studio.js` | חוזה התחום המשותף לדפדפן ולשרת: רכיבים, תקציר, פעילות, אימות וגרסה לשיתוף |
| `app/lib/resilience-studio-ui.js` ו־`.css` | זרימת העבודה, עריכה, גרסאות, שמירה, ייבוא/ייצוא ועיצוב |
| `harness/lib/studio.mjs` | גבול השרת: הרשאות, מיפוי מצרפי, מקורות ציבוריים, סכמות וקריאת Responses API |
| `harness/practice-server.mjs` | שרת Node הקיים; הנתיב `POST /api/studio` |
| `app/lib/access-guard.js`, `harness/lib/access.mjs` | כניסה, אסימון חתום, שמירה לפי זהות ובדיקת הרשאות חיה |
| `app/lib/resilience-advisor-sources.js` | בנק המקורות המקצועי הקיים; מקור האמת |
| `harness/tests/studio-*.test.mjs` | בדיקות חוזה התחום, השרת, ניווט והרשאות, והדפסה |

האתר סטטי: Netlify מפרסם את `app/` לפי `netlify.toml`. שרת ה־Node שב־`harness/` נפרס ב־Render. שינוי בחוזה הפעילות מחייב התאמה בדומיין המשותף, בממשק, בסכמות ובבדיקות השרת; אין להוסיף מימוש מקביל של אותו חוזה.

## גבולות מידע שחייבים להישמר

- כל פעולה מוגנת מאמתת בשרת אסימון חתום וגם מצב הרשאות עדכני: קוד, תוקף, מנוי ותקרת מוסד. הרשאה שמוצגת בדפדפן אינה מספיקה.
- מיפוי נכנס רק בבחירה מפורשת ובבדיקת הרשאת חוסן, מוסד ומפתח ניהול. למודל מגיע סיכום קבוצתי מהשרת; בלי שמות מוסד/כיתה, מזהי נשאלים, תשובות אישיות או מפתח ניהול. אין ממוצע בין סבבים.
- מקורות מקצועיים מגיעים מבנק הידע. מקורות `hidden` אינם נשלחים למודל ואינם מועתקים לערכה, גם בכניסת מנהלת מערכת. חומר משתמש הוא הקשר/השראה בלתי מאושרים; קישור בלי תוכן אינו מקור שנקרא. `existing-bank` מתאר מקור ואינו אישור לפעילות.
- העבודה נשמרת מקומית לפי `sbeUserKey`, על בסיס הזהות באסימון הכניסה החתום. השמירה אינה מוצפנת ואינה מגינה מפני מי ששולט במכשיר. חומר משתמש אינו נשמר אוטומטית בשרת.
- קובץ העבודה האישי ב־JSON מאפשר המשך במכשיר אחר וכולל תקציר פרטי וגרסאות. אסימונים, מפתחות ניהול ושורות משיבים אינם נכללים בו. חומרי המשתתפים והגרסה לשיתוף נבנים מהחלקים המשותפים בלבד; אין קישור ציבורי אוטומטי לעבודה.
- שינויים מוצעים נשארים מועמד עד שהמשתמש מקבל אותם. מחיקת שלב מסירה את טענות הרכיב והמיומנות שהתבססו עליו. תוכן ומקורות שמספק משתמש הם נתונים, ואין לציית להוראות מוטמעות בהם.

## התוספות האחרונות שמומשו

ארבע ההרחבות מומשו בענף ונבדקו מקומית עם נתוני בדיקה ותשובות מודל מדומות:

1. **התייעצות חוזרת עם AI** לאורך התכנון וגם לגבי כל שלב בפעילות: שאלות המשך, בירור ושיפור שנבחר בידי המשתמש, עם שמירת היסטוריית העבודה.
2. **חששות פרטיים של המוביל/ה**, עם עידוד מעשי, פעולות קטנות וחלופות הנחיה. החששות והשיחה עליהם אינם חומר למשתתפים או לגרסה לשיתוף.
3. **מדריך למידה למנחה המבוסס על המקורות**: הסבר על המנגנון, מה ללמוד לפני ההנחיה ואיך ליישם, עם עקיבות למקורות הציבוריים. אין להמציא מקור או להציג פעילות חדשה כמוכחת.
4. **מנגנונים חברתיים חוזרים הניתנים לעריכה**: כיצד ממשיכים את הפעולה בשגרה, מי שותף ואחראי, באיזו תדירות, מה עושים ואיך בודקים פעולה נצפית. מנגנון אינו רק הבטחה כללית ל״שייכות״.

בודקים בכל הרחבה שהמידע החדש נשמר ב־JSON, שהשינוי אינו מוחק עבודה קודמת ושפרטים פרטיים אינם דולפים בהדפסה או בשיתוף. מעדכנים גם את תרחישי הקבלה לפי המימוש בפועל.

## בדיקות והפעלה

מתוך תיקיית `harness/`:

```powershell
node --test tests
```

אין צורך להתקין חבילות בשביל בדיקות אלה. ב־Windows, אם משתמשים ב־Node מהסביבה המצורפת והוא נתקל בהגבלת גישה בעת פתרון קישורים סימבוליים, מריצים את אותו Node עם:

```powershell
node --preserve-symlinks --preserve-symlinks-main --test tests
```

הבדיקות המקומיות משתמשות במודל ובמחסן הרשאות מדומים. מוסיפים בדיקות משמעותיות לסכמות חדשות, הרשאות, שימור גרסאות והפרדת מידע פרטי; בודקים גם עריכה והדפסה ב־RTL בדפדפן. אין להשתמש בנתוני תלמידים אמיתיים בבדיקות.

ב־Render מגדירים `OPENAI_API_KEY` בצד השרת בלבד, `STUDIO_MODEL=gpt-6.1-sol`, ואת תשתית ההרשאות הקיימת `SUPABASE_URL` ו־`SUPABASE_SERVICE_KEY`. אין לשמור מפתח במאגר או בדפדפן. לאחר פריסה נדרשות בדיקות עם הרשאות אמיתיות ו־AI חי; בדיקות הקוד אינן מוכיחות איכות המלצה או יעילות מקצועית. קטלוג הרכיבים, מנגנונים וכללי גיל/נוער/חירום עדיין טעונים אישור מקצועי.
