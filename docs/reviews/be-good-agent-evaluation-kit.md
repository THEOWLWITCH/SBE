# Be Good — ערכת השוואה לצוות הסוכנים

**07.10.2026 · הכנה לבדיקות בלבד.** הערכה זו אינה תוצאה של הרצת מודלים. לא בוצעה קריאה בתשלום. כל המקרים סינתטיים, ואסור להחליף אותם בנתוני תלמידים בלי הסכמה והרשאה מתאימות. [תכנית העבודה](be-good-agent-work-plan.md) היא מקור הדרישות; [המקרים המובנים](be-good-agent-evaluation-cases.json) הם חומר עבודה לשילוב ברתמת U1/U6.

## כיצד לערוך את ההשוואה

1. מתקנים תחילה את חוזי הגישה, הספק, הפרטיות והפלט; מריצים את המקרים ללא API עם ספק מדומה.
2. מקבעים prompt, input, source catalogue, model, effort ו-schema versions. שני המסלולים מקבלים אותו הקשר מורשה ואותם אילוצים.
3. מסלול A משתמש בסוכן יחיד עם אותו ידע וכללי מוצר. מסלול B משתמש בצוות המומחים ובעורך. אין למסלול B גישה למידע שאין ל-A.
4. מציגים תוצרים בסדר אקראי ובתוויות A/B שאינן מסגירות את המסלול. יעל/מנחות בודקות לפחות עשרה זוגות. מודל נוסף יכול להציע ביקורת, אך אינו מחליף את הבדיקה האנושית.
5. לפני קריאות בתשלום קובעים תקרת עלות וזמן לניסוי; רושמים עלות מלאה של reviewers, עורך, retries וסינתזה. אין לקבוע עלות סמך מחיר המודל בלבד.
6. בוחרים מראש מדד איכות ראשי מתוך המחוון להלן. שומרים על כל מגבלות הבטיחות והפרטיות. צוות יתקדם לפיילוט רק אם יתרונו חוזר בכמה מקרים, ואין כשל חמור או נסיגה במדד חובה. מדגם זה מספק החלטת פיילוט ראשונית ולא הוכחת יעילות חינוכית.

## מחוון לביקורת אנושית

| ממד | 0 — חסר/מטעה | 1 — חלקי | 2 — ניתן לשימוש לאחר אישור |
|---|---|---|---|
| התאמה למטרה | הפעילות אינה בודקת/מפתחת את המטרה | קשר כללי בלבד | הפעולות וראיות ההצלחה קשורות למטרה |
| גיל והקשר | התאמה שגויה או הנחות נסתרות | חלק מהאילוצים מכוסים | הקהל, הזמן והמשאבים מכוסים; החסרים גלויים |
| חוסן ומיומנויות | תוויות כלליות או טענת שיפור לא מבוססת | רכיבים מוצגים בלי מנגנון | מטרה, רכיבי חוסן, מיומנויות אישיות/משותפות וקשר לפעולות |
| הנחיה | אין דרך מעשית להנחות | יש פתיחה/סיום אך חסרה תגובה לקושי | הנחיות, ניסוחי שאלות, השתתפות, גבולות והתאמה לקבוצה |
| חששות ועידוד | ביטול החשש או הבטחת הצלחה | אמפתיה כללית | הכרה בחשש, שאלה מועילה וצעד אפשרי; בלי אבחון |
| מקורות ואי־ודאות | מקור מומצא או השערה מוצגת כעובדה | מקור קיים אך שימושו לא ברור | מקור מאושר ומגבלות; עובדה/השערה/הצעה מובחנות |
| סמכות ובחירה | שינוי/שיתוף אוטומטי | אפשרות עריכה אך שינוי לא ברור | לפני/אחרי, חלופות ומחלוקות; אדם מאשר גרסה וקהל |
| ישימות ומנגנון חברתי | התחייבות שאי אפשר לקיים | תדירות/אחריות חלקיות | תדירות, אחראית, גיבוי ומשאב; פרט חסר מסומן |

**תנאי חובה נפרדים מהציון:** בידוד מוסדי, סיווג מידע, מקור מורשה, שדה נעול, סכמה, בעלות job, ביטול/תפוגה ומניעת חיוב כפול. כשל באחד מהם אינו מתקזז בציון פדגוגי גבוה. טיוטה חסרה יכולה להישמר כפרטית ומסומנת; היא אינה מאושרת לשימוש משותף.

## טופס תוצאה לכל זוג

לרשום case ID, reviewer ID (ללא שם אדם), artifact/version, run IDs, prompt/schema/source/model versions, שמונה ציוני המחוון, pass/fail של תנאי החובה, סתירות בין הצעות, מספר עריכות, דקות עד תוצר מאושר, latency ועלות. להוסיף נימוק קצר להעדפה A/B/אין הבדל עם ראיה מהתוצר. מידע רגיש אינו נכתב בטופס; הפניה לגרסה פרטית נעשית בהרשאה בלבד.

ל-Claude: שלב את המקרים ברתמה בלי לפצל את מקור האמת של R/AE/KTD. אם מקרה אינו תואם לסכמה הסופית, עדכן את המבנה תוך שמירת תוצאת הקבלה המצופה; אל תשנה ציפייה כדי להכשיר כשל.
