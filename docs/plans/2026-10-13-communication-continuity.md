## Committed shared contract

`app/lib/communication-core.js` supplies versions, principles, action/revision keys, statuses, entry kinds in Node and browser. All public API calls: POST `/api/communication-continuity`, body `{token,action,...}`. Every response `{conversations}` for list or `{conversation}` for create/get/update/append/editDraft/markSent/generate/extract. Export returns `{conversation}`; delete `{deleted:true}`. Errors `{code,error}` with appropriate HTTP status; never content in logs. Mutations use `expectedRevision` and UUID `requestId`; same request returns prior outcome without duplicate entries. UUID `id` identifies conversation. Recheck live permission before every operation and before storing AI results.

Conversation: `{id,title,audience,status,createdAt,updatedAt,revision,rounds,entries,versions}`. Entry: `{id,kind,text,at,versions,model?,why?,next?,analysis?,revisions?,source?,draftId?,sentEntryId?}`. Revision snapshots contain `{text,at,versions,model?}`. Raw entries never overwritten by generated summaries. `append` accepts `{kind:'received'|'sent'|'note',text}`. `editDraft` accepts `{entryId,text}` and saves previous version. `markSent` accepts `{entryId,text?}` and adds a separate sent snapshot with draft linkage, idempotently; later edits cannot alter sent snapshots. `update` accepts allowlisted `{title,audience,status}`. `generate` accepts `{mode:ACTION_KEY,instruction?,entryId?,revisionStyle?}`; revision is a new draft with parent linkage. Close generates a draft, explicit status update resolves. `extract` accepts `{attachment:{kind:'image'|'pdf'|'text',name,mediaType?,data?,text?}}`; saves successfully extracted full text as received with source metadata; binary is transient and never persisted. UI discloses provider processing before upload. Unreadable extraction creates no falsely successful entry.

Server reads canonical full history, never client system prompts. The AI unit exports `generateCommunication({conversation,action,instruction,revisionStyle,draft,provider}) -> {output,summaries,model}` and `extractCommunicationAttachment({attachment,provider}) -> {text,source,model}`. Output `{message,why,next,clarification,analysis}`. Essential missing fact gives clarification and no message. For analysis/summary/next, message may be empty, explanatory result is available. Analysis fields `{facts,interpretations,control,influence,outsideControl,responsibility,resources,barriers,agreements,openQuestions,followUp}` are string arrays, with uncertainty explicit. `summaries` are structured context-summary entries; retain raw data and source entry IDs. Model `{provider,id}` from actual configured provider. No invented names, agreements, feelings, policies or outcomes; user data treated as untrusted content. New module narrowly follows current user's referral/concise-output direction over global historical rules, preserving other tools.
